## Summary

In-development revision of the Niger drought AA framework. The core two-arm trigger idea is retained from the 2024-10-24 endorsed version (IRI seasonal forecast + an ENACTS/CHIRPS-derived observational arm; OR logic between arms), but the branch carries **two separate, unreconciled candidate redesigns** rather than one proposal: (1) a percentile / rolling-10-year-reference explorer, deployed as an interactive WASM app, that still defaults to the endorsed forecast threshold (35%) with an unresolved observational threshold (15% vs. the PDF's 35%); and (2) a materially different **detrended, fixed-rank-count design** — a full draft report (`index.qmd`, marked "DRAFT — NOT FOR DISTRIBUTION") that removes a documented declining trend in IRI forecast probabilities before setting thresholds, and explicitly balances the forecast and observational arms to trigger in an equal number of years. Neither candidate has been adopted; candidate (2) has been untouched since 2026-05-19, while candidate (1) keeps gaining work.

Since the prior sync, the repo's work has moved from `iri-trend` onto a new branch, `export-historical-trigger-data`, which merges all of `iri-trend`'s history and adds two things: a formal historical backtest export of candidate A's default design (`exports/`, still marked "DRAFT — not for distribution"), and a new, separate **live-monitoring page** (`docs/rainfall/`) that checks how the 2026 season is tracking against the 15%-threshold observational arm using ERA5/CHIRPS proxies, since the real ENACTS SPI isn't published yet. Both proxies currently read at or below the 15% rainfall threshold for 2026, though the page's own implied-SPI cross-check stops just short of triggering on both — worth watching, not a confirmed activation (see Monitoring). No new framework PDF has been published.

## Method

Two distinct methodologies are being explored in parallel to keep the trigger within the CERF-required ~3.5-year combined return period, plus two older single-purpose notebooks that fed earlier percentile analysis, plus (new this pass) a formal backtest export and a live-monitoring stopgap page:

1. **Rolling-window percentile explorer** (`exploration/rolling_threshold_marimo.py`, the notebook behind the app deployed to GitHub Pages — but the deployed WASM export is well behind this source; see Monitoring and Discrepancies). For each evaluation year (2001–2025) and forecast month (Jan–Jun), the threshold is the *k*-th highest value in a rolling **prior-10-year** reference window (locks thresholds to real observed values, no interpolation). Two consecutive months over threshold trigger the forecast arm. The observational arm compares the "Aug" column to a **fixed** threshold from the full historical record. Sliders default to forecast **35%** and observational **15%** — i.e. it currently reproduces the endorsed PDF's forecast value but not its observational value. Each consecutive forecast pair is assigned to a window by its **decision (later) month** — Jan+Feb/Feb+Mar → Window 1; Mar+Apr/Apr+May/May+Jun (or the obs arm) → Window 2 — the same logic now formalised in the export script below.

2. **Historical trigger data export** (`exploration/export_trigger_data.py`, `exports/` — new this pass, commits 81cf22d/f8098c6). Replicates candidate A's default design (forecast 35%, obs 15%, rolling 10-yr window, eval 2001–2025) as self-contained CSVs: `iri_maproom_raw.csv` (the raw Maproom input), `forecast_month_thresholds.csv` (per year×month rolling thresholds), `trigger_history.csv` (annual per-arm/per-window trigger flags), and `trigger_stats.csv` (per-window RP/activation-probability summary). A bug in the initial cut (81cf22d) mis-assigned the Mar+Apr forecast pair to Window 1; f8098c6 fixed it to assign by decision month — matching, not changing, the app's own existing logic — "reproducing the authoritative per-window statistics" (Window 1 RP 8.7yr/12%, years 2001/2009/2011; Window 2 RP 4.3yr/23%, years 2001/2004/2006/2013/2022/2023; combined RP 3.3yr/31%, years 2001/2004/2006/2009/2011/2013/2022/2023). Its own README labels the export "DRAFT — not for distribution."

3. **2026 Jun–Jul rainfall monitoring page** (`exploration/jun_jul_rainfall_make_data.py` + `exploration/jun_jul_rainfall_page.py` → `docs/rainfall/index.html` — new this pass, commits 9f2c442/16cedb8). The real ENACTS Jun–Jul SPI for 2026 isn't published on the Maproom yet, so this page evaluates 2026 Jun–Jul rainfall over the monitored zone (Niger south of 17°N) in ERA5 reanalysis and CHIRPS v2.0 as **stopgap proxies**, comparing each against its own 1991–2025 15%-value-locked threshold and, via a linear fit to the historical Maproom SPI record, an *implied* 2026 SPI value. Originally built as a marimo notebook (9f2c442); rebuilt in 16cedb8 as hand-authored static HTML with embedded matplotlib PNGs ("same content and numbers as before") — no marimo/WASM runtime needed for this page. See Monitoring for the resulting numbers.

4. **Detrended, fixed-rank-count design** (`index.qmd`, rendered to `docs_quarto/`, explicitly banner-marked **"DRAFT — NOT FOR DISTRIBUTION"**; untouched since 2026-05-19). Applies a two-step detrend to the full 1991–2025 IRI record — beta regression to remove a declining trend in below-normal forecast probabilities, then variance-standardisation of the residuals — before calibrating thresholds over 1998–2025 (28 years). Only the six forecast columns are detrended; the observational "Aug" column is merged back raw and thresholded raw (presented in the report's table as if detrended — see Discrepancies). Thresholds are **fixed rank counts**: forecast arm = top 3 years per month (≈10.7%) in detrended space, two consecutive months required; observational arm = bottom 5 years (≈17.9%) — chosen so both arms fire in the **same number of years (5 each)**. Combined, 8 of 28 years ≈ 1-in-3.6. Traces to the grid-search in `exploration/detrending.md`/`detrending_marimo.py`.

5. **Two further percentile notebooks** (`exploration/iri_trend.md`, `exploration/full_trigger.md`) explore yet another family of methods, and disagree with each other as well as with the two candidates above. `iri_trend.md` sets thresholds as full-record quantiles and argues a flat 0.30 per-month percentile keeps activation probability acceptable where 0.35 is too high (only touched this pass by a trivial added cell, `8/28`, no substantive change). `full_trigger.md` selects forecast quantile 0.55 / 4 obs years, firing 8 of 28 years ≈ 1-in-3.6 — a third calibration, much wider on the forecast side than either candidate. Both are unchanged in substance since the prior sync.

## Trigger logic

- **Keys off:** IRI forecast probability of below-average JAS rainfall (OCHA Certification model, Frequency 35%, exported from the Maproom 25 Apr 2026) for months Jan–Jun; an August-reported observational indicator (the "Aug" column of the same export — labelled "ENACTS MON Jun–Jul SPI" in the marimo app and the new export script, but "August rainfall z-score (CHIRPS-based)" in `index.qmd`; same column, conflicting provenance labels — see Discrepancies) for the observational arm.
- **Decision rule (plain language) — candidate A, rolling-window percentile (`rolling_threshold_marimo.py`, deployed as the GH Pages explorer; now also formalised as a CSV export):** a year triggers if **either** arm fires (OR). The forecast arm fires if any two *consecutive* months (Jan+Feb, Feb+Mar, Mar+Apr, Apr+May, or May+Jun) both land in the top *X%* of their respective rolling 10-year reference windows (app default X=35%). The observational arm fires if the Aug value is in the bottom *Y%* of the full historical record (app default Y=15%).
- **Decision rule (plain language) — candidate B, detrended fixed-rank-count (draft report):** the same OR-of-two-arms structure, but the per-month forecast threshold is fixed at "the 3rd-highest **detrended** value on record" (≈top 10.7%), and the observational threshold at "the 5th-lowest **raw** Aug value on record" (≈bottom 17.9%, = −0.483) — chosen so both arms independently trigger 5 of the 28 analysis years.

## Key decisions & rationale

The branch is driven by the same underlying concern as before — does the endorsed 35% per-month forecast threshold still produce the intended ~3.5-year combined return period? — but the repo has not settled on one answer. Two genuinely different statistical philosophies are being explored:

- **Percentile thresholding on a rolling reference window** (candidate A) keeps the trigger adaptive to recent climate/model conditions but does not correct for any long-run trend within that window. This pass added a formal, reproducible backtest export of this design (`exports/`) — useful for anyone wanting exact historical trigger years/RPs without re-running the notebook — but its own README marks it "DRAFT — not for distribution," so it is documentation of candidate A, not a step toward adoption.
- **Detrending before thresholding** (candidate B, `index.qmd`) instead argues the real issue is a genuine multi-decade decline in below-normal forecast probabilities, which biases a naive historical-percentile threshold toward recent years. It fits a beta-regression trend + variance model on the full 1991–2025 record, then sets fixed-rank thresholds in the detrended space, explicitly choosing counts that make the forecast and observational arms equally likely to fire. This is the more statistically developed candidate but remains an explicit draft, not for distribution, untouched since 2026-05-19, and drops the two-window package structure the CERF budget lines are built around.
- **New, orthogonal work this pass** (the rainfall-monitoring page) isn't a redesign candidate at all — it's an attempt to answer, ahead of the real ENACTS SPI publication, whether the *existing* observational arm is likely to fire this season. It reinforces, rather than resolves, the standing 15%-vs-35% threshold question: at 15% both proxies sit right on the edge (rainfall-mm test triggers on both, implied-SPI cross-check triggers on neither), while the page itself says a 35% threshold would make a trigger near-certain.

Both candidates were locked to real historical observed values for the forecast threshold (no interpolation) — a design constraint carried over from the endorsed version, aimed at interpretability for stakeholders.

Candidate A is the only design tested against external ground truth: its simulated trigger years are set against an (undocumented) independent severity ranking and real CERF drought Rapid Response allocations. That strengthens the evidentiary case for candidate A specifically, but it is a one-sided addition, not a reconciliation between the designs.
