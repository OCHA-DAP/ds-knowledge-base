## Summary

In-development revision of the Niger drought AA framework. The core two-arm trigger idea is retained from the 2024-10-24 endorsed version (IRI seasonal forecast + an ENACTS/CHIRPS-derived observational arm; OR logic between arms), but the `iri-trend` branch now carries **two separate, unreconciled candidate redesigns** rather than one proposal: (1) a percentile / rolling-10-year-reference explorer, deployed as an interactive WASM app, that still defaults to the endorsed forecast threshold (35%) with an unresolved observational threshold (15% vs. the PDF's 35%); and (2) a materially different **detrended, fixed-rank-count design** — a full draft report (`index.qmd`, marked "DRAFT — NOT FOR DISTRIBUTION") that removes a documented declining trend in IRI forecast probabilities via beta regression before setting thresholds, and explicitly balances the forecast and observational arms to trigger in an equal number of years. Neither candidate has been adopted. Candidate (1) still frames its results as Window 1 / Window 2 by decision month but attaches no budgets; candidate (2) drops the window/package structure entirely. No new framework PDF has been published.

## Method

Two distinct methodologies are being explored in parallel to keep the trigger within the CERF-required ~3.5-year combined return period, plus two older single-purpose notebooks that fed earlier percentile analysis:

1. **Rolling-window percentile explorer** (`exploration/rolling_threshold_marimo.py`, the notebook behind the app deployed to GitHub Pages — but note the deployed WASM export is ~2 months behind this source; see Monitoring and Discrepancies). For each evaluation year (2001–2025) and forecast month (Jan–Jun), the threshold is the *k*-th highest value in a rolling **prior-10-year** reference window (locks thresholds to real observed values, no interpolation). Two consecutive months over threshold trigger the forecast arm. The observational arm compares the "Aug" column to a **fixed** threshold from the full historical record. Sliders default to forecast **35%** and observational **15%** — i.e. it currently reproduces the endorsed PDF's forecast value but not its observational value. A "closest-to-target-RP" percentile is computed live for stakeholders to explore, but is not itself a proposed new default. The app also cross-checks its simulated trigger record against two external series: a hardcoded year-by-year drought-severity ranking (`bad_year_rank`, 1991–2021, provenance undocumented — see Discrepancies) and real CERF Rapid Response drought allocations for Niger (`aa.cerf_allocation`/`aa.cerf_supplement`, hardcoded from a 2026-07-30 DB query). Spearman rank correlations are reported between severity and both trigger status and indicator margin; the CERF figures are a display column in the year-by-year activation table only, not an input to any correlation. **What changed since the prior sync (afef129 → 1073c22):** the indicator-margin correlation panel and the CERF column were added **to this notebook**; the `bad_year_rank` join and the trigger-status correlations already existed at afef129 and were simply unrecorded on the prior page. A commented-out precursor of the same two-series cross-check survives in `exploration/full_trigger.md`, so this is a re-activation of an earlier idea rather than a wholly new line of work — additional evidence for candidate A, not a resolution of the two-candidate impasse. **What changed since the prior sync (1073c22 → dbdc180, 2026-08-03, three commits, all cosmetic/presentation — no threshold, window, or indicator changes):** (a) the notebook and the committed **static snapshot** gained an EN/FR language toggle (`-lang` CLI arg drives prose/table/figure language; terminology sourced from the team's own doc-based glossary, `docs/I18N.md`) — the interactive app, which takes no CLI args, renders English; (b) the per-year trigger-detail table dropped its "T" trigger marks in favour of red fill alone, added light per-column rules, and the 2022 CERF figure is now footnoted "$9.5M\*" with "\*Anticipatory allocation under the AA framework itself" — a small but useful confirmation, from the repo's own hand, that the CERF figure it displays and correlates against is the AA-triggered allocation and not a different CERF window; (c) the static snapshot moved from `docs/static/` to `docs/static/2026/` (English) and `docs/static/2026/fr/` (French), with the old `/static/` and `/static/fr/` paths kept alive as meta-refresh redirect stubs (all four paths return 200 live, checked 2026-08-04). Slider defaults are unchanged (forecast 35% / observational 15%). **Important caveat on all of the above:** none of it reached the **deployed interactive** app. `docs/index.html` was last regenerated at 1a5fa3a (2026-06-03), so the explorer a stakeholder opens at the Pages root still has no CERF column, no indicator-margin panel, no W1/W2 columns and no language plumbing — only the static snapshot does (verified 2026-08-04 by decoding its embedded `<marimo-code>`; see Discrepancies).

2. **Detrended, fixed-rank-count design** (`index.qmd`, rendered to `docs_quarto/`, explicitly banner-marked **"DRAFT — NOT FOR DISTRIBUTION"**). Applies a two-step detrend to the full 1991–2025 IRI record — beta regression (bounded to (0,1), appropriate for probability data) to remove a declining trend in below-normal forecast probabilities, then a linear variance-standardisation of the residuals — before calibrating thresholds over 1998–2025 (28 years). **Only the six forecast columns are detrended**; the observational "Aug" column is merged back in raw and thresholded in raw space (the report's threshold table nonetheless presents it alongside the detrended ones — see Discrepancies). Thresholds are set as **fixed rank counts**: forecast arm = top 3 years per month (≈10.7%) in detrended space, requiring two consecutive months; observational arm = bottom 5 years (≈17.9%) — chosen so both arms fire in the **same number of years (5 each)**, explicitly correcting what the report calls an imbalance in "an earlier version of this framework" that fired far more often on the observational arm than the forecast arm. Combined, the two arms fire in 8 of 28 years ≈ a **1-in-3.6** combined return period (target stated as 1-in-3.5). Forecast thresholds are then back-transformed to raw forecast-probability space for 2026–2027 (see Trigger windows) — because the detected trend is declining, the 2026/2027 raw thresholds (~24–29% depending on month) are *lower* than the flat 35% used today. This design traces to the grid-search in `exploration/detrending.md`/`detrending_marimo.py`, which searched all (n_above, n_below) combinations and selected the point where both arms trigger 5 years each.

3. **Two further percentile notebooks** (`exploration/iri_trend.md`, `exploration/full_trigger.md`) explore yet another family of methods, and disagree with each other as well as with the two candidates above. `iri_trend.md` is the branch's oldest artifact (2025-04 → 2026-04) and the only one on the older export `ner_trigger_comparison_2025_newmodel_adjustment - raw.csv` (`skiprows=3`); it sets thresholds as **full-record quantiles** and argues that a flat 0.30 per-month percentile — applied to the forecast months *and* the Aug column alike — keeps overall activation probability acceptable where 0.35 is too high. What it sweeps by start year is the **return-period accounting period**, not the threshold reference window. ## Trigger logic

- **Keys off:** IRI forecast probability of below-average JAS rainfall (OCHA Certification model, Frequency 35%, exported from the Maproom 25 Apr 2026) for months Jan–Jun; an August-reported observational indicator (the "Aug" column of the same export — labelled "ENACTS MON Jun–Jul SPI" in the marimo app but "August rainfall z-score (CHIRPS-based)" in `index.qmd`; same column, conflicting provenance labels — see Discrepancies) for the observational arm.
- **Decision rule (plain language) — candidate A, rolling-window percentile (`rolling_threshold_marimo.py`, deployed as the GH Pages explorer):** a year triggers if **either** arm fires (OR). The forecast arm fires if any two *consecutive* months (Jan+Feb, Feb+Mar, Mar+Apr, Apr+May, or May+Jun) both land in the top *X%* of their respective rolling 10-year reference windows (app default X=35%). The observational arm fires if the Aug value is in the bottom *Y%* of the full historical record (app default Y=15%).
- **Decision rule (plain language) — candidate B, detrended fixed-rank-count (draft report):** the same OR-of-two-arms structure, but the per-month forecast threshold is fixed at "the 3rd-highest **detrended** value on record" (not a %, though it works out to ≈top 10.7%), and the observational threshold at "the 5th-lowest **raw** Aug value on record" (≈bottom 17.9%, = −0.483) — chosen so both arms independently trigger 5 of the 28 analysis years.
- **Activation structure:** candidate A retains an implicit window split by decision month (Jan+Feb/Feb+Mar → "Window 1"; Mar+Apr/Apr+May/May+Jun or the observational path → "Window 2"), matching the endorsed version's packages. Candidate B does **not** split into windows/packages at all — it is a single undifferentiated forecast-arm/observational-arm system.
- **Calibration:** both candidates target a combined return period ≈3.5 years (the CERF minimum). Candidate A calibrates via historical percentile thresholds over a rolling reference window; candidate B calibrates via a detrended fixed-rank count, explicitly correcting for a documented declining trend in IRI forecast probabilities (so that a historical percentile threshold would otherwise over-favour recent years). Neither calibration has been adopted as the design for a future endorsement.
- **Authoritative source:** none — this is a development version; no framework PDF exists for this trigger design, and the two candidate designs disagree with each other. The repo on `iri-trend` is the only source. The 2024-10-24 PDF remains authoritative for the *endorsed* trigger.
- **Operated by:** the production trigger surface remains IRI Maproom 2 (operated with WFP/AGRHYMET/DMN/DNPGCA), running the endorsed 35%/two-window design — outside this repo, and unaffected by either candidate redesign explored here.

## Key decisions & rationale

The branch is driven by the same underlying concern as before — does the endorsed 35% per-month forecast threshold still produce the intended ~3.5-year combined return period? — but the repo has not settled on one answer. Two genuinely different statistical philosophies are being explored:

- **Percentile thresholding on a rolling reference window** (candidate A) keeps the trigger adaptive to recent climate/model conditions but does not correct for any long-run trend within that window. The earlier `iri_trend.md` analysis pointed the same way — that the endorsed 35% overfires ("activation probability is too high no matter how late we set the start date of analysis… if we adjust the per-month percentile threshold to `0.3`, we're ok") — but it reached that conclusion with full-record quantiles and a start-year sweep of the RP accounting, not with candidate A's rolling window. `full_trigger.md`, on the same export as the app, went the *other* way and settled on a much wider forecast arm (top 55%) balanced by a narrower 4-year observational arm; nothing in the repo reconciles the three.
- **Detrending before thresholding** (candidate B, `index.qmd`) instead argues the real issue is a genuine multi-decade decline in below-normal forecast probabilities (attributed tentatively to partial Sahelian rainfall recovery since the 1970s–80s drought era, and/or IRI model climatology changes), which biases a naive historical-percentile threshold toward recent years. It fits a beta-regression trend + variance model on the full 1991–2025 record, then sets fixed-rank thresholds (top-3/bottom-5 of the last 28 years) in the detrended space, explicitly choosing counts that make the forecast and observational arms equally likely to fire — a deliberate correction to the endorsed version's imbalance (which fires disproportionately via the wide 35% observational arm). This is the more statistically developed candidate, including forecast-skill validation (ROC AUC, JAS SPI correlation) not present anywhere else in the repo, but it is explicitly a draft, not for distribution, and drops the two-window package structure that the CERF budget lines are built around.

Both candidates were locked to real historical observed values for the forecast threshold (no interpolation) — a design constraint carried over from the endorsed version, aimed at interpretability for stakeholders.

Candidate A is the only design tested against external ground truth: its simulated trigger years are set against an (undocumented) independent severity ranking and, since 2026-07-30, against real CERF drought Rapid Response allocations. That strengthens the evidentiary case for candidate A specifically, but it is a one-sided addition, not a reconciliation between the designs — and the severity ranking's own credibility can't be assessed until its source is documented. Note also that the same two series appear, commented out, in the older `full_trigger.md`, so the idea predates the current app.
